# DYA 连接重启与高负载风险修复 · 2026-10-15

用户报告连接 DYA 后 Cube 重启且异常发热。只读 USB 检查确认运行态设备掉线，未取得 panic 日志，因此没有确认实机根因；不能排除供电或电池异常。异常发热时保持断电，不为采集日志持续通电。

本次修复不改变管脚、充电、电源或音频设置，不擦除 NVS：

- 将 protobuf Reader 内联字段从 16 缩至 4，普通消息仍支持 16 字段，显式 repeated 仍最多 128；多出的字段受限地放到堆中，避免多层解码器同时占用大任务栈。
- 快速 keymap 默认模型改为不可变共享对象；只有 pending 请求才加载已保存模型，使用堆上目标，不在每次请求建立两个大模型。
- 相同 macOS clang++、-Os 测得 FastKeymap 自身栈帧从 7408 降为 1312 字节，RPC Handle 从 4336 降为 2896 字节。这不是 ESP32 实测，也不是完整调用链峰值。SDK 构建附带 cube_studio 的 .su 报告，供检查目标编译器结果。
- USB 读取失败也必须阻塞；同步循环无论出错还是持续有数据，都至少阻塞一个 tick，给 idle、Wi-Fi 和音频任务调度机会。
- 同一会话发送失败后，停止该批次剩余通知，避免每条通知累积两秒等待而超过十秒看门狗。收到新完整请求或重新连接后才允许重试；处理完整请求时更新配置任务看门狗。
- 标准及快速 keymap 都返回最大层容量 4，而不是剩余层数。
- 新增只读文本命令 `DONGLE DIAG`：reset、uptime_ms、heap_free、heap_min、sync_stack_free。它不复位、不写配置，仅请求时回复，不把异步 ESP 日志插入 DYA 二进制流。仍不是完整 panic 堆栈。

新增本地优化栈预算、错误读取阻塞、循环调度、发送失败批次保护和层容量测试。修复集中提交后只构建 Cube 双模一次，左右手固件无需重编。没有自动刷机，也不能用编译通过宣布发热已消除。
